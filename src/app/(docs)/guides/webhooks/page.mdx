# Webhooks

Chatty webhooks deliver real-time, cryptographically signed JSON payloads to your servers whenever key events happen across your bots — eliminating the need for periodic API polling.

Use webhooks to synchronize captured leads with your CRM, log conversation transcripts in external data warehouses, trigger downstream workflows in **n8n / Zapier / Make**, or notify your on-call team in Slack.

---

## Event Catalog

Chatty supports the following webhook event topics:

| Event Topic | Description | Trigger Moment |
|---|---|---|
| `lead.created` | New lead captured | A visitor provides their contact details (name, email, phone) in chat. |
| `message.user` | Visitor message received | A customer sends a new message on any channel (widget, WhatsApp, Instagram, etc.). |
| `message.assistant` | Bot response generated | The AI bot generates and delivers a response. Includes model latency metrics. |
| `booking.confirmed` | Calendar meeting booked | A visitor selects a time slot and schedules an appointment via Google / Outlook integration. |
| `handoff.requested` | Human operator escalation | Visitor triggers handoff intent or AI confidence drops below configured threshold. |
| `csat.submitted` | Customer feedback submitted | Visitor rates the conversation (1–5 stars) and optionally submits text feedback. |
| `session.started` | Conversation initialized | A visitor opens the widget and exchanges the first message. |
| `session.ended` | Conversation closed | Session times out after 30 minutes of inactivity or is resolved by an operator. |
| `product.updated` | Catalog item modified | Price, inventory, or metadata changes occur on manual catalog products. |

## Registering Webhooks

### Via Dashboard

1. Navigate to **Dashboard → Developer API → Webhooks**.
2. Click **Create Webhook Subscription**.
3. Enter your HTTPS endpoint URL (e.g. `https://api.yourcompany.com/webhooks/chatty`).
4. Select the event topics you wish to subscribe to.
5. Click **Save Webhook**.
6. Chatty generates an **HMAC Signing Secret** (e.g. `whsec_3fa85f64...`). Copy this secret immediately; it is displayed once for security.

### Via Developer REST API

<CodeGroup>
```bash title="Register Webhook Subscription"
curl -X POST "https://api.chatty.personaliai.com/api/v1/webhooks" \
  -H "Authorization: Bearer chatty_sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://api.yourcompany.com/webhooks/chatty",
    "events": [
      "lead.created",
      "booking.confirmed",
      "handoff.requested"
    ]
  }'
```

```bash title="List Active Webhooks"
curl -X GET "https://api.chatty.personaliai.com/api/v1/webhooks" \
  -H "Authorization: Bearer chatty_sk_..."
```

```bash title="Delete Webhook"
curl -X DELETE "https://api.chatty.personaliai.com/api/v1/webhooks/{webhook_id}" \
  -H "Authorization: Bearer chatty_sk_..."
```
</CodeGroup>

## Cryptographic Signature Verification

Every incoming HTTP POST request includes the `X-Chatty-Signature` header. This signature is an **HMAC-SHA256 hash** of the raw HTTP request body calculated using your webhook's secret key.

Always verify the signature before processing payloads to prevent spoofing or replay attacks:

<CodeGroup>
```python title="Python (FastAPI / Flask)"
import hmac
import hashlib

def verify_chatty_signature(raw_body: bytes, signature_header: str, secret: str) -> bool:
    """Verify incoming X-Chatty-Signature header against raw body bytes."""
    computed = hmac.new(secret.encode("utf-8"), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(computed, signature_header)
```

```typescript title="TypeScript / Node.js"
import crypto from "crypto";

export function verifyChattySignature(rawBody: Buffer, signatureHeader: string, secret: string): boolean {
  const hmac = crypto.createHmac("sha256", secret);
  hmac.update(rawBody);
  const computed = hmac.digest("hex");
  return crypto.timingSafeEqual(Buffer.from(computed), Buffer.from(signatureHeader));
}
```

```php title="PHP"
function verify_chatty_signature(string $rawBody, string $signatureHeader, string $secret): bool {
    $computed = hash_hmac("sha256", $rawBody, $secret);
    return hash_equals($computed, $signatureHeader);
}
```

```go title="Go"
package main

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
)

func VerifyChattySignature(rawBody []byte, signatureHeader string, secret string) bool {
    mac := hmac.New(sha256.New, []byte(secret))
    mac.Write(rawBody)
    expected := hex.EncodeToString(mac.Sum(nil))
    return hmac.Equal([]byte(expected), []byte(signatureHeader))
}
```
</CodeGroup>

<Warning title="Use Raw Request Body">
Verify signatures against the **raw, unparsed HTTP request body**. Parsing the body as JSON before verification can alter whitespace or key order, causing signature validation to fail.
</Warning>

## Retry Policy & Dead-Letter Queue (DLQ)

If your endpoint returns an HTTP status outside the `2xx` range or fails to respond within **10 seconds**, Chatty triggers automated exponential backoff retries:

| Attempt | Wait Duration Before Next Retry |
|---|---|
| Attempt 1 | Immediate |
| Attempt 2 | 1 second |
| Attempt 3 | 5 seconds |
| Attempt 4 | 30 seconds |
| Attempt 5 | 5 minutes |
| Attempt 6 | 30 minutes |
| Attempt 7 | 2 hours |
| Attempt 8 | 8 hours (Final Attempt) |

After 8 failed attempts, the delivery is marked as `failed` and preserved in your bot's **Dead-Letter Queue (DLQ)**. You can view failed deliveries, inspect response codes, and manually replay them from **Dashboard → Developer API → Webhook Logs**.

<Tip title="Handle Webhooks Asynchronously">
Respond with `200 OK` as soon as the signature is verified, and push the payload to an asynchronous queue (such as Redis BullMQ, RabbitMQ, SQS, or Celery) for background processing.
</Tip>

## Product Catalog & E-Commerce Webhooks

Manual products and WooCommerce store catalogs can also be kept updated via real-time webhooks. When products change in external PIMs or ERP systems, send signed updates to:

```text
POST https://api.chatty.personaliai.com/api/v1/catalog/events
```

```json title="Product Update Payload"
{
  "event": "product.updated",
  "bot_id": "YOUR_BOT_ID",
  "external_id": "ERP-SKU-992",
  "item": {
    "title": "Ultra-light Titanium Camping Stove",
    "price": 49.99,
    "inventory_count": 142,
    "in_stock": true,
    "url": "https://mystore.com/products/titanium-stove"
  }
}
```

For complete details on connecting WooCommerce stores with automated webhook synchronization, see the [WooCommerce Integration Guide](/guides/woocommerce).

## Local Development & Testing

When developing webhooks locally, use tunnels like [ngrok](https://ngrok.com) or [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) to provide an HTTPS endpoint:

```bash
ngrok http 3000
# Forwarding https://abc1234.ngrok-free.app -> http://localhost:3000
```

Register `https://abc1234.ngrok-free.app/webhooks/chatty` in the Chatty dashboard to receive live events during local testing.
